PSIR - PlayStation Inspired Renderer

A PlayStation-inspired fixed-point 3D renderer written in strict ANSI C (C89).

The project explores the architectural constraints and visual characteristics of the original PlayStation while remaining practical on modern hardware. Core transformation, projection, and geometry processing are implemented using fixed-point arithmetic, while Modern OpenGL 4.5 Direct State Access (DSA) is used as a rasterization backend.

The goal is not cycle-accurate hardware emulation, but rather the recreation of classic PS1-era rendering techniques, limitations, and visual artifacts within a clean, modular, and portable codebase.
Features
Core Architecture

    Strict ANSI C89 codebase
    Explicit state-based design (no global renderer state)
    Modular subsystem separation
    Portable build system
    SDL2 platform layer

Fixed-Point Geometry Pipeline

    Q3.12 fixed-point math engine
    Matrix and vector transformations
    Camera-space calculations
    Perspective vertex projection
    Hardware-inspired GTE-style transformation pipeline
    Near-plane clipping

PS1-Inspired Visual Characteristics

    Affine texture mapping (noperspective)
    RGB555 color precision emulation
    Color quantization and banding
    CLUT (Color Look-Up Table) texture support
    Low-resolution framebuffer rendering
    Pixel-perfect nearest-neighbor scaling

Modern Rendering Backend

    OpenGL 4.5 Core Profile
    Direct State Access (DSA)
    Immutable buffer storage
    Dynamic geometry batching
    Single-frame geometry streaming
    Single draw-call rendering path

Project Structure

/gte

Design Philosophy

This renderer intentionally embraces many limitations associated with late-1990s 3D hardware.

Rather than hiding artifacts behind modern rendering techniques, the project reproduces them where practical:

    fixed-point arithmetic
    affine texture distortion
    limited color precision
    CLUT-based textures
    low internal rendering resolutions
    hardware-inspired transformation stages

The result is a renderer that visually resembles early PlayStation-era graphics while leveraging modern GPUs for efficient rasterization.
Technical Compromises

Several implementation choices differ from original PlayStation hardware by necessity.
Dynamic Geometry Batching

The original PlayStation submitted primitives through command packets and ordering tables generated by the CPU.

On modern desktop systems, issuing individual draw calls for each primitive would introduce unnecessary CPU and driver overhead. Instead, all transformed primitives are accumulated into a single CPU-side vertex stream and uploaded once per frame.

This allows the renderer to preserve its PS1-inspired transformation pipeline while remaining efficient on modern hardware.
OpenGL Rasterization

Transformation logic, projection, fixed-point arithmetic, color quantization, and texture processing are implemented by the project itself.

Final triangle rasterization is delegated to OpenGL rather than a fully software-based rasterizer.

This tradeoff significantly reduces complexity while preserving the characteristic visual appearance of PS1-era graphics.
Frame Timing

Original PlayStation applications were synchronized to fixed PAL/NTSC refresh intervals.

Modern systems operate across a wide range of display refresh rates and scheduling behavior. The renderer therefore uses high-resolution timing and delta-time clamping to maintain stable simulation behavior.
Building
Fedora

Install dependencies:

sudo dnf install SDL2-devel glew-devel libpng-devel make gcc

Clone and build:

git clone https://github.com/programistac/psir.git

cd psir

make

Run:

./psx_demo

Clean build artifacts:

make clean
